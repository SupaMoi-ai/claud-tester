# HerCode: project rules
Calm, mobile-first prototype of a life-management app for women with ADHD, with an optional partner companion app called BroCode. Goal: reduce mental load, not add another productivity system. No backend, auth, real AI, HealthKit or real push notifications. Mock and simulate.

Stack: Vite + React + TypeScript, Tailwind, shadcn/ui (Drawer/vaul for bottom sheets), Lucide, Framer Motion, Zustand with persist (localStorage, versioned key), Vitest, Playwright (screenshots only).
Scripts to keep working: dev, typecheck (tsc --noEmit), test, build, and "shots" (Playwright opens the dev server at 390x844, visits every screen, saves PNGs to /screenshots). If the browser is missing, run npx playwright install chromium.

Architecture: /components, /features (today, brain, calendar, patterns, cycle, partner, review, onboarding), /domain (types, buildDayPlan, insights, projectForPartner), /mock (seed, mockAI), /copy.ts. Logic lives in pure /domain functions; UI only renders their results. One store. Seed history is generated deterministically (seeded RNG), so Patterns is computed from real events. CapacityLevel is one enum ('minimum' | 'light' | 'normal' | 'high') with one label map: Bare minimum / A little / Normal / I actually have energy. askAI(intent, context): Promise<AIResponse> has a 600-900ms shimmer delay and deterministic keyword rules, so a real LLM can replace it later.

Privacy (non-negotiable): everything is Private by default; every item that could reach BroCode has a sensitivity field (private | shared | signal). projectForPartner(state) is the ONLY source for the BroCode preview, which must not import private store slices. A unit test proves no private, cycle, health, mood or note data appears in the projection by default. Exact cycle detail is shareable only via an explicit toggle, off by default, with a plain-language confirmation.

Copy: all strings in /copy.ts. Use "Possible pattern", "Based on your check-ins", "You've reported...", "HerCode noticed...". Never use causal hormone claims, "you should", "overdue", "failed", "behind", streaks, exclamation marks or cheerleading. Postponed items are "moved". No red states; "attention" uses apricot. One line in Cycle and Patterns: "Personal observations, not medical advice." Add a Vitest test that scans /copy.ts for banned words.

Design: background #FAF7F2, surface #FFFFFF, ink #2B2A28, muted #8A857D; accents sage #B9CBB8, dusty blue #B7C9D9, sand #E8DCC8, apricot #F0CDB6, lavender-grey #CFC8E0 (cycle only). Card radius 24, round chips, soft shadows. Serif display font (Fraunces or similar) for headings, clean sans (Inter or DM Sans) for UI, body at least 16px. Touch targets at least 48px, important actions max 2 taps, one primary action per screen. Motion 150-250ms, respect prefers-reduced-motion. 430px phone frame centered on desktop, full-bleed with safe-area insets on a phone. English UI, 24h time, NOK, Monday-first weeks.

Working agreements: one milestone at a time. At the end of each: run typecheck, tests, build and shots; look at the screenshots; fix overflow, clipped text and small tap targets; confirm state persists across reload; commit; stop with a summary of at most 5 lines. No empty placeholder screens (cut depth, not screens). Make reasonable product decisions yourself; ask only when a decision is expensive to reverse.
